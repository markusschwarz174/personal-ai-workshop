# The Workshop Model

## Purpose

Personal AI Workshop helps one person build and preserve a practical collection of AI-assisted ways of working.

The workshop begins with the person's real problem, not with a predefined agent team. Its packages grow from repeated use, correction, and evidence.

## Five principles

1. **One entry.** Every session can begin at the same intake.
2. **Dialogue before routing.** Missing context is collected before a package is recommended.
3. **Different packages may be built differently.** A simple question should not inherit an enterprise workflow.
4. **Validation matches the risk.** Ideas, plans, changes, and outcomes require different checks.
5. **Experience is curated.** A run log is not automatically a reusable lesson.

## Workshop parts

| Part | Job |
|---|---|
| ADVISER | Clarifies the request and recommends a package plus entry role. |
| Package catalog | Lists available packages and their routing conditions. |
| Package | Owns one class of work from entry to exit. |
| Role | Performs one responsibility inside a package. |
| Pass | A bounded unit of work with explicit inputs and outputs. |
| Validator | Independently checks the relevant error class. |
| Human gate | Gives or refuses authority to continue. |
| Post-box | Carries an explicit handover to a named recipient. |
| Experience store | Keeps reviewed lessons that may help future work. |

## Small before elaborate

Start with the smallest package that can solve a repeated problem. Add roles, files, gates, and automation only after real use proves they are needed.
